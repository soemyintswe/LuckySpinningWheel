# Lucky Wheel အသုံးပြုပုံလမ်းညွှန်

ဤလမ်းညွှန်သည် ကံစမ်းသူ/အလှူရှင်များနှင့် Admin တို့အတွက် ဖြစ်ပါသည်။ App ကို [luckydraw-mksdev.web.app](https://luckydraw-mksdev.web.app) မှဖွင့်ပြီး browser ဟောင်း cache မဖြစ်စေရန် လိုအပ်သည့်အခါ `Ctrl + Shift + R` ဖြင့် ပြန်ဖွင့်ပါ။

## ၁။ ကံစမ်းသူနှင့် အလှူရှင် အသုံးပြုပုံ

### အကောင့်ဖွင့်ခြင်းနှင့် ဝင်ခြင်း

1. **အသင်းဝင်စာရင်းသွင်းရန်** ကိုနှိပ်ပြီး အမည်၊ ဖုန်း၊ Email နှင့် စကားဝှက်ဖြည့်ပါ။ Google ဖြင့်ဝင်ခြင်းလည်းရပါသည်။ Facebook ကို Firebase Authentication တွင် Admin က ဖွင့်ထားမှ အသုံးပြုနိုင်ပါသည်။ အကောင့်အသစ် ပထမဆုံးဝင်ချိန်တွင် Website က Firestore အသင်းဝင် profile ကို UID အလိုက် အလိုအလျောက်ဖန်တီးပြီး Admin ၏ Website အတည်ပြုစာရင်းထဲ ပို့ပေးပါသည်။
2. Viber နှင့် Telegram အချက်အလက်သည် ဆက်သွယ်ရန်အတွက်သာဖြစ်ပြီး အဲဒီအကောင့်များဖြင့် တိုက်ရိုက်ဝင်ခြင်း မဟုတ်ပါ။
3. အကောင့်ကို တစ်ကြိမ်သာဖွင့်ပါ။ Admin အတည်ပြုပြီးမှ မဲအစီအစဉ်များတွင် ဝင်နိုင်ပါမည်။ အကောင့်အတည်ပြုခြင်းသည် မဲတစ်ခုချင်းစီအတွက် ကံစမ်းခွင့်တောင်းခြင်းနှင့် မတူပါ။
4. နောက်တစ်ကြိမ်ဝင်ရန် **အကောင့်ဝင်ရန်** ကိုသုံးပါ။ အကောင့်အချက်အလက်မှ Profile ပုံ URL နှင့် ကိုယ်ရေးအချက်အလက်များ ပြင်နိုင်ပါသည်။ Profile မဖန်တီးနိုင်သည့် အမှားပြလျှင် အကောင့်အမည်ကိုနှိပ်ပြီး Account modal ထဲက **Firestore profile** အခြေအနေကိုစစ်ကာ အင်တာနက်ပြန်စစ်၍ Website မှ ထပ်စမ်းပါ။ UID အလိုက် profile ကို Website က ဖန်တီးပေးသောကြောင့် Firestore Console ထဲသို့ ကိုယ်တိုင်ဝင်ပြင်ရန်မလိုပါ။

### မဲအစီအစဉ်ထဲ ဝင်ခြင်း

1. **မဲအစီအစဉ်များ** မှ မိမိဝင်လိုသော မဲကိုရွေးပါ။ အခြေအနေ၊ စာရင်းဖွင့်ချိန်၊ မဲဖောက်ချိန်နှင့် ဝင်ခွင့်ပုံစံကို ကြည့်ပါ။
2. စာရင်းဖွင့်ချိန်ရောက်ပြီး မဲမပိတ်သေးပါက **ကံစမ်းခွင့်ရယူရန်** ကိုနှိပ်ပါ။ မဲတစ်ခုစီအတွက် တစ်ကြိမ်စာရင်းတင်နိုင်ပြီး Admin သတ်မှတ်ထားသော လူတစ်ဦးချင်းအများဆုံးနှင့် လက်ကျန်မဲအရေအတွက်အတွင်းသာ ရွေးနိုင်ပါသည်။ အခမဲ့မဲ၏ ပုံမှန်ကန့်သတ်ချက်မှာ တစ်ဦးလျှင် ၁ မဲဖြစ်သည်။
3. ဖုန်းနှင့် ဆုလက်ခံရန် ဆက်သွယ်ရန်အချက်အလက် ဖြည့်ပါ။ ပစ္စည်းဆုအတွက် လိပ်စာဖြည့်ပါ။ ငွေသားဆုရပါက အဆင်ပြေစေရန် KBZPay, WavePay, AYA Pay, CB Pay, ဘဏ်အကောင့် သို့မဟုတ် အခြားနည်းလမ်းကို ရွေး၍ အကောင့်ပိုင်ရှင်အမည်နှင့် ဖုန်း/အကောင့်နံပါတ်ကို ရွေးချယ်ဖြည့်နိုင်ပါသည်။
4. အခမဲ့မဲဆိုလျှင် တောင်းဆိုချက်ကို ပို့ပါ။ ရောင်းချမဲဆိုလျှင် မဲဈေးနှုန်းအလိုက် စုစုပေါင်းပမာဏကိုစစ်ပြီး ငွေပေးချေမှုအချက်အလက်ဖြည့်ပါ။ Promotion/ပွိုင့်မဲဆိုလျှင် လိုအပ်သည့်ပွိုင့်ပြည့်ရပါမည်။ Admin သည် မဲဖန်တီးချိန်တွင် ကျန်ပွိုင့်ကို အကောင့်ထဲသယ်ပြီး နောက်မဲတွင်သုံးခွင့်ပြုခြင်း သို့မဟုတ် အတည်ပြုချိန်၌ ကျန်ပွိုင့်ကိုပါ သုံး/သက်တမ်းကုန်စေခြင်းကို ရွေးနိုင်သည်။ App တွင် ငွေလွှဲ/ငွေလက်ခံမှု အလိုအလျောက်မလုပ်ပါ။
5. ပို့ပြီးလျှင် အခြေအနေသည် **စစ်ဆေးဆဲ** ဖြစ်ပါမည်။ Admin က မဲဝင်ခွင့်ကို အတည်ပြုပြီးမှ လှည့်ခွင့်ရပါမည်။ ငွေပေးချေမဲနှင့် ပွိုင့်မဲတွင် Admin က ငွေလွှဲ/ပွိုင့်ကို စစ်ဆေးပါမည်။
6. အတည်ပြုပြီးနောက် မဲဖောက်ချိန်ရောက်မှ မဲစာရင်းဘေးရှိ **ကိုယ်တိုင်လှည့်** ခလုတ်ကိုနှိပ်ပါ။ Admin က ခွင့်ပြုထားမှ ကိုယ်တိုင်လှည့်ခွင့်ရပါမည်။ Admin က တစ်ကြိမ်လျှင် တစ်လှည့် သို့မဟုတ် လက်ကျန်ခွင့်အားလုံးကို အစုလိုက်လှည့်ရန် ရွေးထားနိုင်ပါသည်။ အစုလိုက်ဆိုလျှင် အတည်ပြုမေးခွန်းပြပြီးနောက် တစ်လှည့်စီကို Firestore ထဲ သီးခြားမှတ်တမ်းတင်ပါမည်။ အသုံးပြုပြီးသည့်အလှည့်ကို ပြန်မရပါ။ မပေါက်သည့်အလှည့်လည်း ဖြစ်နိုင်ပါသည်။

### ဆုရပြီးနောက်

- **ဆုရရှိသူများ** တွင် မိမိဆုနှင့် လွှဲပေးမှုအခြေအနေကိုကြည့်ပါ။ ဆုကို Admin ထံမှ လက်ခံရရှိသောအခါ Admin က **ဆု လွှဲပေးပြီး** ဟုမှတ်တမ်းတင်ပါမည်။ အဲဒီအချိန်မှ ငွေ/ပစ္စည်းလက်ကျန်စာရင်းမှ ထုတ်ယူပါသည်။
- မိမိဆုကို အလှူပြန်ထည့်ရန် သို့မဟုတ် အခြားအတည်ပြုအသင်းဝင်ထံ လွှဲရန် ဆုကတ်ပေါ်ရှိ **ဆုကို လှူ/လွှဲရန် တောင်းဆို** ကိုနှိပ်ပါ။ လွှဲမည့်သူအတွက် account Email ထည့်ပြီး အတည်ပြုပါ။ Admin စစ်ဆေးအတည်ပြုပြီးမှ ဆောင်ရွက်မည်။

### အလှူစာရင်းတင်ခြင်း

**အလှူရှင်များ** မှ အလှူစာရင်းထည့်ပါ။ ငွေသား သို့မဟုတ် ပစ္စည်း၊ တန်ဖိုး/အရေအတွက်၊ ဆက်သွယ်ရန်နှင့် ပုံ URL ကိုဖြည့်ပြီးပို့ပါ။ Admin အတည်ပြုပြီးမှ စာရင်းရှင်းတမ်းထဲဝင်ပါမည်။

## ၂။ Admin အသုံးပြုပုံ

### အကောင့်နှင့် ဝင်ခွင့်ကို စီမံခြင်း

1. ပိုင်ရှင်က Firebase တွင် `admins/{Firebase Auth UID}` document ကို `role: "admin"` ဖြင့် ကြိုတင်သတ်မှတ်ထားရပါမည်။ Admin ခလုတ်များမပေါ်ပါက အကောင့် modal မှ UID နှင့် Admin document အခြေအနေကို စစ်ပါ။
2. **မဲနှိုက်သူများ** စာမျက်နှာရှိ **အကောင့်အတည်ပြုရန်** အပိုင်းမှာ အကောင့်အသစ် Register လုပ်သူများကို စစ်ပြီး **ခွင့်ပြုရန်** သို့မဟုတ် ပယ်ချပါ။ ဤအဆင့်သည် အကောင့်ကို မဲအားလုံးဝင်ခွင့်ပြုခြင်းဖြစ်သည်။
3. အောက်ဘက် **မဲနှိုက်သူများ** ဇယားမှာ ရွေးထားသော မဲတစ်ခုအတွက် တောင်းဆိုထားသည့် ကံစမ်းခွင့်ကို သီးခြားစစ်ပါ။ အခမဲ့မဲတွင် စာရင်းနှင့် အရေအတွက်ကိုစစ်ပြီး ခွင့်ပြုပါ။ ရောင်းချမဲတွင် ငွေလွှဲမှုကို၊ ပွိုင့်မဲတွင် ပွိုင့်/ကူပွန်ကို အပြင်ဘက်မှစစ်ပြီးမှ အတည်ပြုပါ။ အတည်ပြုချိန်တွင် လက်မှတ်ဝင်ငွေကို ledger ထဲသို့ထည့်ပြီး ပွိုင့်မဲဆိုလျှင် သတ်မှတ်ပွိုင့်ကို ဖြတ်ပါမည်။
4. မဲဝင်သူ၏ ဆက်သွယ်ရန်နှင့် ငွေသားဆုလက်ခံရန် အကောင့်အချက်အလက်ကို ထိုဇယားတွင်ကြည့်နိုင်ပါသည်။ ထိုအချက်အလက်များကို အများမြင်ရသည့် Winner စာမျက်နှာတွင် မပြသပါနှင့်။
5. အကောင့်စီမံခန့်ခွဲမှုတွင် အခြားအသင်းဝင်ကို ဆိုင်းငံ့၊ ပြန်ဖွင့်၊ မှတ်တမ်းတင်ပယ်ဖျက်နိုင်ပါသည်။ ဖျက်ခြင်းသည် ကိုယ်ရေးအချက်အလက်ကို ဖယ်ရှားပြီး မှတ်တမ်းကို audit အတွက်ထားသည့် soft delete ဖြစ်သည်။ Firebase Authentication user ကိုယ်တိုင်ဖျက်ခြင်း မဟုတ်ပါ။

### မဲအစီအစဉ်ဖန်တီးခြင်းနှင့် ပြင်ဆင်ခြင်း

1. **မဲအသစ်ဖန်တီးရန်** ကိုနှိပ်ပါ။ အမည်၊ အကြောင်းအရာ၊ ပုံ URL (မဖြစ်မနေမဟုတ်)၊ အခမဲ့/ရောင်းချ/ပွိုင့်ပုံစံ၊ စုစုပေါင်းမဲအများဆုံး၊ လူတစ်ဦးချင်းအများဆုံးနှင့် အချိန်ဇယားကိုဖြည့်ပါ။ အတည်မပြုသေးသော တောင်းဆိုမဲကိုလည်း လက်ကျန်မှ ကြိုတင်ဖယ်ထားသဖြင့် စုစုပေါင်းကန့်သတ်ချက် မကျော်ပါ။ ပယ်ချလျှင် လက်ကျန်သို့ ပြန်လည်လွှတ်ပေးပါမည်။
2. **စာရင်းဖွင့်မည့်ရက်/အချိန်** သည် ဝင်ခွင့်တောင်းဆိုမှုစတင်နိုင်မည့်အချိန်ဖြစ်သည်။ **မဲဖောက်မည့်ရက်/အချိန်** သည် ဝင်ခွင့်ပိတ်ပြီး Wheel စလှည့်နိုင်မည့်အချိန်ဖြစ်သည်။ ဒေသစံတော်ချိန်ကိုစစ်ပြီး ဖောက်ချိန်ကို ဖွင့်ချိန်နောက်တွင်ထားပါ။
3. အကြိမ်များစွာပြုလုပ်မည်ဆိုလျှင် 1–24 ကြိမ်နှင့် အကြိမ်ကြားရက်အရေအတွက်ကို သတ်မှတ်ပါ။ App က အကြိမ်တစ်ခုချင်းစီကို သီးခြား raffle အဖြစ်၊ သတ်မှတ်ထားသောရက်ခြားဖြင့်ဖန်တီးပါမည်။
4. ငွေဆုတစ်ခုချင်းစီ၊ ပစ္စည်းတန်ဖိုး/အရေအတွက်၊ စုစုပေါင်းဆုငွေကန်နှင့် နှစ်သိမ့်ဆုအရေအတွက်ကို ထည့်ပါ။ နှစ်သိမ့်ဆုကို ကျန်ငွေညီမျှခွဲခြင်း (ကျပ်ပြည့်) သို့မဟုတ် ဆုတစ်ဆုစီပုံသေငွေဖြင့် သတ်မှတ်နိုင်သည်။ ပုံသေဆုစုစုပေါင်းသည် ငွေကန်ထက် မကျော်ရပါ။ ရောင်းချမဲအတွက် ဈေးနှုန်းနှင့် ငွေလက်ခံမည့် ဘဏ်/Wallet ကိုဖြည့်ပါ။
5. **မဲအစီအစဉ်များ** စာမျက်နှာ သို့မဟုတ် အနှစ်ချုပ်စာမျက်နှာမှ **ပြင်ဆင်ရန်** ကိုနှိပ်ပါ။ စာရင်းဝင်သူ/လှည့်မှုရှိပြီးသားဆိုလျှင် အမည်၊ ဖော်ပြချက်၊ ပုံ၊ အချိန်ဇယား၊ စုစုပေါင်း/လူတစ်ဦးချင်း မဲကန့်သတ်ချက်နှင့် Wheel လှည့်ခွင့်ပုံစံကိုလည်း ပြင်နိုင်သည်။ ဆု၊ ဈေးနှုန်းနှင့် ငွေကြေးစည်းကမ်းများကို မပြောင်းနိုင်ပါ။ မဲဝင်ခွင့်တောင်းဆို/အတည်ပြုပြီးသည့်အရေအတွက်ထက် မဲအများဆုံးကို လျှော့၍မရပါ။ Wheel ကို ကံစမ်းသူ၊ ဒိုင် သို့မဟုတ် နှစ်ဖက်လုံးလှည့်ခွင့် ပေးနိုင်ပြီး တစ်ခါလျှင် တစ်မဲစီ သို့မဟုတ် လက်ကျန်အားလုံးကို အစုလိုက် လှည့်စေမည်ကို သတ်မှတ်နိုင်သည်။
6. User များသည် မဲစာရင်းပိတ်/ဖောက်မည့် ရက်အချိန်ကို မဲကတ်ပေါ်တွင် မြင်ရမည်။ မဲဖောက်ချိန်မတိုင်မီ မိနစ် ၃၀ အတွင်း Countdown ပေါ်လာပြီး သုညရောက်လျှင် ကိုယ်တိုင်လှည့်ခွင့်ရှိသူများ စတင်လှည့်နိုင်ပါသည်။

### မဲဖောက်ခြင်းနှင့် ဆုစီမံခြင်း

- မဲဖောက်ချိန်ရောက်လျှင် **မဲအစီအစဉ်များ** မှ **ဒိုင်လှည့်** ကိုနှိပ်ပါ။ လက်ကျန်လှည့်ခွင့်ရှိသည့် အတည်ပြုမဲစာရင်းများမှ စနစ်က ရွေးချယ်ပါမည်။ ကံစမ်းသူကလည်း မိမိအတည်ပြုစာရင်းမှ ကိုယ်တိုင်လှည့်နိုင်ပါသည်။
- မဲဖောက်ချိန်ရောက်လျှင် မဲကတ်ရှိ **Wheel ဖွင့်ရန်** ကိုနှိပ်ပြီး Wheel modal ထဲက အလယ်ခလုတ်ကိုနှိပ်မှသာ လှည့်ပါမည်။ ဆုစာရင်း slot တစ်ခုစီက Wheel segment တစ်ခုဖြစ်ပြီး transaction ထဲက ရလဒ်နှင့် Wheel ရပ်မည့် segment ကို တိုက်ရိုက်ချိတ်ထားသည်။ မျှားတံရပ်ပြီးမှသာ ဆုအမည်နှင့် တန်ဖိုးကို ပြပါမည်။ ကံစမ်းခွင့်တစ်ကြိမ်သုံးပြီးပါက ပြန်မရ၊ ဆု slot တစ်ခုကို တစ်ကြိမ်သာ ပေးနိုင်ပါသည်။
- Wheel ကိုနှိပ်စတင်လိုက်လျှင် နောက်ခံတီးလုံးနှင့် Wheel လည်သံ ဖွင့်ပါမည်။ Wheel modal အပေါ်ဘက်ရှိ **အသံဖွင့်ထားသည်/အသံပိတ်ထားသည်** ခလုတ်မှ အသံကို ပိတ်/ပြန်ဖွင့်နိုင်ပြီး ရွေးချယ်မှုကို ဤ Browser တွင် မှတ်ထားပါမည်။ ပထမ၊ ဒုတိယ၊ တတိယဆုအတွက် သီးခြားအောင်ပွဲသံနှင့် ဆုအဆင့်လိုက် အရောင်စုံ confetti လှုပ်ရှားမှု ပြပါမည်။ Browser တွင် အသံပိတ်ထားပါက tab ကိုအသံဖွင့်ပြီး ထပ်စမ်းပါ။
- ဆုကို အမှန်တကယ်လွှဲပေးပြီးမှ **ဆု လွှဲပေးပြီး** ကိုနှိပ်ပါ။ လက်ရှိ UI တွင် **ဆု ပြန်သိမ်း** သည် `လွှဲပြောင်းပြီး` အခြေအနေရှိသောဆုတွင်သာ ပေါ်ပါသည်။ မလွှဲရသေးသော `လွှဲပေးရန်ကျန်` ဆုကို ပြန်သိမ်းရန် လုပ်ဆောင်ချက် မပါသေးသဖြင့် မလွှဲပေးဘဲ `လွှဲပြောင်းပြီး` ဟု မှားယွင်းမှတ်တမ်းမတင်ပါနှင့်။ ပြန်သိမ်းပြီးပါက အကြောင်းပြချက်နှင့် ledger အဝင်ကို မှတ်တမ်းတင်ပါမည်။
- ကံထူးရှင်၏ ဆုလှူ/လွှဲတောင်းဆိုမှုများသည် **ဆုရရှိသူများ** စာမျက်နှာထိပ်တွင်ပေါ်ပါမည်။ အချက်အလက်စစ်ပြီးမှ အတည်ပြု/ပယ်ချပါ။
- ငွေဆုကတ်တွင် ကံစမ်းခွင့်တောင်းစဉ် ကံထူးရှင်ရွေးထားသော Bank/Wallet၊ လက်ခံသူအမည်၊ အကောင့်နှင့် မှတ်တမ်းတင်ထားသည့် ဆုတန်ဖိုးကို Admin သာမြင်နိုင်သည်။ **လွှဲရန်အချက်အလက် ကူးယူ** ဖြင့် အချက်အလက်ကို ကူးပြီး Wallet/Bank မှ ကိုယ်တိုင်လွှဲပါ။ လွှဲပြီးကြောင်း စစ်ဆေးပြီးမှ **ဆု လွှဲပေးပြီး** ကိုနှိပ်ပါ။ ဤ App တွင် လက်ရှိ provider payment API ချိတ်ဆက်ထားခြင်းမရှိသဖြင့် Wallet ထဲသို့ အလိုအလျောက်မလွှဲပါ။ ငွေပမာဏပါဝင်ပြီး Wallet က တိုက်ရိုက်လက်ခံသည့် QR အတွက် သက်ဆိုင်ရာ provider ၏ merchant/API ခွင့်နှင့် ပေါင်းစည်းမှုအချက်အလက် လိုအပ်သည်။

### အလှူ၊ ငွေ/ပစ္စည်းစာရင်းနှင့် အစီရင်ခံစာ

- **အလှူရှင်များ** တွင်တင်ထားသော အလှူကို စစ်ဆေးပြီး အတည်ပြုပါ။ အတည်ပြုလျှင် ငွေ သို့မဟုတ် ပစ္စည်းအဝင်ကို ledger ထဲသို့ တစ်ကြိမ်စာရင်းသွင်းပါမည်။
- **ငွေ/ပစ္စည်းစာရင်း** မှ လက်ကျန်ညှိရန်ကိုသုံး၍ စာရင်းအဝင်/အထွက်၊ ပစ္စည်းအရေအတွက်၊ တစ်ခုတန်ဖိုးနှင့် မှတ်ချက်ကို ထည့်ပါ။ လက်တွေ့အဝင်/အထွက်နှင့် ကိုက်ညီအောင် ထည့်ပြီး မှတ်တမ်းမရှိဘဲ လက်ကျန်ကို မပြင်ပါနှင့်။
- **အစီရင်ခံစာ** မှ CSV ဒေါင်းလုဒ်လုပ်ပါ။ Excel သို့မဟုတ် Sheets ဖြင့်ဖွင့်ပြီး လိုအပ်သည့်ကာလ/အမျိုးအစားအလိုက် စစ်ဆေးနိုင်ပါသည်။ CSV တွင် လက်ရှိစာရင်းများပါဝင်ပြီး payout အကောင့်အချက်အလက်ကို မပါဝင်စေပါ။

- **`3 + 5 ဆု`** သည် ဆုအဆင့် ၃ ခုနှင့် နှစ်သိမ့်ဆု ၅ ခု၊ စုစုပေါင်း ၈ slot ကို ဆိုလိုသည်။ **`3 / 7 မဲ`** သည် အတည်ပြုထားသော မဲ ၃ စောင် / စုစုပေါင်းခွင့်ပြုမဲ ၇ စောင်ကို ဆိုလိုပြီး ဆုအရေအတွက်မဟုတ်ပါ။ ဆု slot စုစုပေါင်းက မဲအများဆုံးထက်များလျှင် App က သတိပေးမည်။ လက်ရှိမဲ၏ အရေအတွက်ကို Admin က သဘောတူပြင်ဆင်မှသာ ပြောင်းပါ။ မဲကတ်တွင် အတည်ပြုပြီး၊ စောင့်ဆိုင်းဆဲနှင့် ကျန်မဲကို ခွဲပြထားသည်။
- အနိုင်ရသူစာရင်းသည် Firestore live listener ဖြင့် အချိန်နှင့်တပြေးညီ ပြောင်းလဲမည်။ ဆု slot တစ်ခုကို တစ်ကြိမ်သာ claim လုပ်နိုင်ပြီး အတည်ပြုမဲတစ်စောင်လျှင် လှည့်ခွင့်တစ်ကြိမ်သာရှိသည်။ ထို့ကြောင့် အတည်ပြုထားသော မဲအရေအတွက်ထက် ပို၍လှည့်မရပါ။ ကန့်သတ်ချက်/အမှားရှိလျှင် App ၏ အသိပေးစာကိုဖတ်ပြီး အချိန်၊ စာရင်းနှင့် လက်ကျန်ကို စစ်ပါ။

## ၄။ လုံခြုံရေးနှင့် ဝန်ဆောင်မှုကန့်သတ်ချက်များ

- Register လုပ်ခြင်း၊ ကံစမ်းခွင့်တောင်းခြင်းနှင့် ငွေပေးချေခြင်းသည် သီးခြားလုပ်ငန်းစဉ်များဖြစ်သည်။ App သည် KBZPay/ဘဏ်မှ ငွေကို တိုက်ရိုက်လွှဲခြင်း သို့မဟုတ် အလိုအလျောက်အတည်ပြုခြင်း မလုပ်ပါ။
- Profile၊ အလှူနှင့် ဆုပုံများကို public HTTPS URL အဖြစ်သိမ်းထားသောကြောင့် link ရှိသူတိုင်း မြင်နိုင်ပါသည်။ လျှို့ဝှက်စာရွက်စာတမ်း သို့မဟုတ် ကိုယ်ရေးအချက်အလက်ပါတဲ့ပုံ မတင်ပါနှင့်။ ငွေလက်ခံမည့် account အချက်အလက်ကိုတော့ private မဲဝင်စာရင်းတွင်သာ သိမ်းပါသည်။
- လက်ရှိ Spark ဗားရှင်းတွင် ကျပန်းရလဒ်ကို browser က ရွေးပြီး Firestore Rules က လှည့်ခွင့်နှင့် ဆု slot ထပ်မရမှုကို ထိန်းချုပ်သည်။ Browser ကျပန်းရွေးချယ်မှုကို Server ဘက်က လွတ်လပ်စွာအတည်ပြုခြင်း မပါသဖြင့် တန်ဖိုးမြင့် သို့မဟုတ် တရားဝင်ထီအဖြစ်အသုံးပြုရန် မသင့်ပါ။

## ၅။ User Account နှင့် Role စီမံခန့်ခွဲခြင်း

1. Admin အကောင့်ဖြင့် ဝင်ပြီး **မဲနှိုက်သူများ** ကိုဖွင့်ပါ။ အောက်ဘက်ရှိ **အသင်းဝင်အကောင့်များ** အပိုင်းတွင် Register လုပ်ထားသူကို ရှာပါ။
2. **ပြင်ရန်** ကိုနှိပ်ပြီး အမည်၊ ဖုန်း၊ Viber/Messenger၊ Telegram၊ လိပ်စာနှင့် Role ကိုပြင်ကာ သိမ်းပါ။ Email နှင့် Password သည် Firebase Authentication credential ဖြစ်သဖြင့် ဤ profile form မှ မပြောင်းပါ။
3. Role များမှာ **ကံစမ်းသူ/အသင်းဝင်**, **အလှူရှင်**, **မဲဖောက်သူ/ဒိုင်**, **Admin** ဖြစ်သည်။ `Admin` Role သတ်မှတ်ရာတွင် website က `admins/{UID}` permission record ကိုပါ စစ်ဆေးပြီးရေးသည်။ ကိုယ်ပိုင် Admin account ကို အခြား Admin တစ်ဦးကသာ ပြောင်းလဲနိုင်သည်။
4. `မဲဖောက်သူ/ဒိုင်` သည် လက်ရှိအဆင့်တွင် profile အမျိုးအစားအဖြစ်သာ မှတ်သားထားပြီး Admin console၊ private participant payout account များဖတ်ခွင့် မရပါ။ ထိုအချက်အလက်များကို Rules ဖြင့် field-level ခွဲထုတ်ပြီးမှ သီးခြား draw-only ခွင့်ကို အနာဂတ်တွင် လုံခြုံစွာပေးနိုင်မည်။
5. **ဆိုင်းငံ့ရန်** သည် app ဝင်ခွင့်ကို ပိတ်သည်။ **ပယ်ဖျက်ရန်** သည် စာရင်းစစ်မှတ်တမ်းများနှင့် ဆု/မဲမှတ်တမ်းများကို ထိန်းသိမ်းပြီး profile ကိုဖယ်ရှားသည့် soft-delete ဖြစ်သည်။ Firebase Authentication login credential ကို Spark client app မှ ဖျက်မပေးနိုင်သဖြင့် လိုအပ်လျှင် Firebase Console မှ သီးခြားပိတ်ပါ။ Admin ကိုဖျက်မည်ဆိုပါက Admin permission ကိုပါရုပ်သိမ်းသည်။
6. Register/Login စကားဝှက်အကွက်ရှိ မျက်လုံးခလုတ်ဖြင့် ခဏပြ/ဖျောက်နိုင်သည်။ Password ကို အခြားသူမြင်နိုင်သည့် screen မှာ မပြပါနှင့်။

## ၆။ ငွေစာရင်း၊ ဘဏ်သွင်း/ထုတ်နှင့် လယ်ဂျာ

- **ငွေ/ပစ္စည်းစာရင်း → စာရင်းသွင်းရန်** တွင် ရက်စွဲ၊ လုပ်ငန်းအကြောင်းအရာ၊ ဘောက်ချာ/လွှဲအညွှန်း၊ ငွေပမာဏ (ကျပ်ကိန်းပြည့်)၊ Debit account၊ Credit account နှင့် မှတ်ချက်တို့ ထည့်ပါ။ Bank/Wallet အကောင့်အမည်ကို သင်နှစ်သက်သလို စံတူအမည်တစ်မျိုးတည်း သုံးပါ (ဥပမာ `KBZ Bank · ****1234`)။
- **ရရှိငွေ/အလှူ/မဲဝင်ငွေ** — Dr ငွေသား/ဘဏ်/Wallet, Cr သက်ဆိုင်ရာ ဝင်ငွေအကောင့်။ **အသုံးစရိတ်ပေးချေ** — Dr အသုံးစရိတ်အကောင့်, Cr ငွေပေးချေသည့်အကောင့်။
- **ဘဏ်/Wallet သို့ ငွေသွင်း** — Debit field တွင် ဘဏ်/Wallet လက်ခံအကောင့်၊ Credit field တွင် ငွေသားရင်းမြစ်ကို ရေးပါ။ **ငွေထုတ်** — Debit field တွင် ငွေသားလက်ခံရာ၊ Credit field တွင် ဘဏ်/Wallet အရင်းအမြစ်ကို ရေးပါ။ **အကောင့်အချင်းချင်းလွှဲ** — Credit field သည် ငွေထွက်သည့်အကောင့်၊ Debit field သည် လက်ခံသည့်အကောင့်ဖြစ်သည်။ ငွေသွင်း၊ ထုတ်၊ လွှဲပြောင်းခြင်းသည် စုစုပေါင်းပိုင်ဆိုင်မှုကို နှစ်ကြိမ်မရေတွက်စေပါ။
- အလှူအတည်ပြုမှု၊ အခကြေးငွေမဲဝင်ငွေနှင့် ဆုလွှဲပေး/ပြန်လည်လက်ခံမှုကို လယ်ဂျာတွင် အလိုအလျောက်ထည့်ပြီး Debit/Credit အကောင့်နှစ်ဖက်ကိုလည်း မှတ်တမ်းတင်သည်။ ပစ္စည်းစာရင်းကို အမျိုးအစားနှင့် ပစ္စည်းအမည်အလိုက် အရေအတွက်/တန်ဖိုးဖြင့် ကြည့်နိုင်သည်။
- လယ်ဂျာတစ်ကြောင်းသည် ပြင်/ဖျက်မရသော append-only audit record ဖြစ်သည်။ မှားယွင်းပါက မူရင်းတန်းကို မဖျက်ဘဲ ဆန့်ကျင်ဘက်တန်ဖိုးရှိသော **ပြန်လည်ပြင်ဆင်/ပြန်တမ်း စာရင်းသစ်** ထည့်ပါ။ ဘောက်ချာဓာတ်ပုံကို ယခု schema တွင် သိမ်းရန်မပါသေးပါ။
- ယခင်ကရှိပြီးသား legacy ledger rows များကို အတင်းအကျပ် ပြောင်းလဲမထားပါ။ ထို rows များတွင် Debit/Credit account မပြည့်စုံနိုင်သဖြင့် ဇယားတွင် `Legacy` ဟုပေါ်ပါက အရင်းအမြစ်အထောက်အထားနှင့် တိုက်စစ်ပြီးမှ အဖွင့်လက်ကျန်စာရင်းကို အသစ်တင်ပါ။ CSV အစီရင်ခံစာတွင် လယ်ဂျာရက်စွဲ၊ ဘောက်ချာ၊ Debit၊ Credit၊ မှတ်ချက်တို့ပါဝင်သည်။
- ဆုလက်ခံပိုင်ခွင့်ကို အခြားအသင်းဝင်ထံ လွှဲပေးခြင်းသည် ပိုင်ရှင်စာရင်းပြောင်းခြင်းသာဖြစ်ပြီး ဘဏ်ငွေထုတ်ထားသည်ဟု မရေတွက်ပါ။ အမှန်တကယ်ပေးချေသည့်အခါမှ ဆုလွှဲပေးပြီးဟု အတည်ပြုပါ။

## ၇။ လက်မှတ်အရေအတွက်၊ ဆုငွေကာမိမှုနှင့် Bank/Wallet ရွေးချယ်စရာများ (Iteration 28)

- မဲအသစ်တွင် အခမဲ့၊ ရောင်းချမဲ၊ Promotion ပွိုင့်/ကူပွန် စနစ်ကိုရွေးပါ။ **စုစုပေါင်းမဲအများဆုံး** သည် စီစဉ်ထားသည့်လက်မှတ်ပမာဏဖြစ်ပြီး **လူတစ်ဦးချင်းအများဆုံး** သည် တစ်ဦးစီ ဝယ်/တောင်းနိုင်သည့်ကန့်သတ်ချက်ဖြစ်သည်။ အခမဲ့မဲအတွက် အများဆုံးမဲကို ၁ ထားလျှင် တစ်ဦးတစ်မဲသာ တောင်းနိုင်သည်။
- ရောင်းချမဲတွင် တစ်စောင်ဈေးနှုန်း × စုစုပေါင်းမဲအများဆုံးကို ခန့်မှန်းဝင်ငွေအဖြစ်ပြသည်။ ဤကိန်းသည် အမှန်တကယ်လက်ခံရငွေမဟုတ်ပါ။ တောင်းဆိုချက်ကို Admin က အတည်ပြုပြီး လယ်ဂျာတွင်မှတ်တမ်းဝင်မှသာ ရောင်းရငွေအဖြစ်ယူဆသည်။ မဲဖောက်ချိန်တွင် အတည်ပြုပြီးရောင်းရငွေသည် ပေးရမည့်ငွေဆုစုစုပေါင်းထက် မများသေးပါက Wheel မလှည့်နိုင်ပါ။ မဲကတ်တွင်လည်း သတိပေးချက်ပေါ်မည်။
- အခမဲ့/ပွိုင့်မဲတွင် ခန့်မှန်းငွေဆုက လယ်ဂျာလက်ကျန်ငွေထက်များပါက ရန်ပုံငွေ သတိပေးချက်ပေါ်မည်။ အလှူ/အခြားရင်းမြစ်ဝင်ငွေကို အရင် လယ်ဂျာတွင် မှတ်တမ်းတင်ပါ။ ရန်ပုံငွေကို တစ်မဲချင်း သီးခြား reserve မလုပ်သေးသဖြင့် တစ်ပြိုင်နက်ဖွင့်ထားသည့် မဲများအတွက် အလားတူငွေကို ထပ်မံအသုံးပြုမိနိုင်ကြောင်း သတိပြုပါ။
- ဆုအစီအစဉ်တွင် ဆုအဆင့်တစ်ခုစီ၏ အရေအတွက်နှင့် တန်ဖိုးကို သတ်မှတ်ပါ။ ဆုအရေအတွက်နှင့် စုစုပေါင်းဆု slot၊ ငွေဆုစုစုပေါင်း/ဆုပစ္စည်းတန်ဖိုး စုစုပေါင်းကို စစ်ပါ။ နှစ်သိမ့်ဆုကို ကျန်ငွေကျပ်ပြည့်အညီမျှခွဲခြင်း သို့မဟုတ် တစ်ဆု ပုံသေသတ်မှတ်ခြင်းဖြင့်တွက်နိုင်သည်။
